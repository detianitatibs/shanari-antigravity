# ブログ機能拡張要件定義書

## 1. 目的
ブログ記事の読みやすさと回遊率を向上させるため、以下の機能を追加する。
1. **目次 (Table of Contents)**: 記事の構造を一目で理解し、目的の箇所へ素早くアクセスできるようにする。
2. **関連記事 (Related Articles)**: 読了後に興味関心の高い記事を提示し、サイト内回遊を促す。

## 2. 機能要件

### 2.1 目次 (Table of Contents)
- **対象**: ブログ記事詳細ページ (`/blog/[slug]`)
- **表示位置**: 記事本文の冒頭（またはタイトル/アイキャッチ画像の下）
- **収集対象**: 本文中の Markdown 見出し (`#`, `##`)。H1, H2 レベルまでを対象とする。
- **機能**:
  - 見出しをクリックすると、該当箇所へスムーズスクロール（またはジャンプ）する。
  - 現在のスクロール位置に応じて、目次内の該当項目がハイライトされることが望ましい（Nice to have）。
- **デザイン**:
  - 記事のデザインに馴染むシンプルなリスト形式。
  - レベルに応じたインデントを行う。

### 2.2 関連記事 (Related Articles)
- **対象**: ブログ記事詳細ページ (`/blog/[slug]`)
- **表示位置**: 記事本文の直後
- **表示内容**: 閲覧中の記事と関連性の高い記事をカード形式で表示する。
- **選定ロジック**:
  1. **タグ (Tags)の一致**: 閲覧中の記事と同じタグを持つ記事を優先して表示する。
  2. **カテゴリ (Categories)の一致**: タグで不足する場合、同じカテゴリの記事を表示する。
  3. **その他**: それでも不足する場合は、最新記事などを補充する（または表示数を減らす）。
- **表示件数**: 1行程度（PC表示で3〜4件、SP表示で横スクロールまたは縦積み数件程度）。過度な表示は避ける。
- **除外条件**: 現在閲覧中の記事自体はレコメンドに含めない。
- **コンポーネント**: 既存のブログ一覧カード (`BlogCard` 等) をベースに、よりコンパクトなデザインを採用する。

## 3. 非機能要件
- **パフォーマンス**: 目次生成や関連記事取得によるページロード時間への悪影響を最小限に抑える。
- **レスポンシブ**: スマートフォン、タブレット、PC それぞれで適切に表示されること。
- **SEO**: 目次による内部リンク構造の強化、関連記事による内部リンクの充実を図る。

## 4. 制約事項
- クリック率などのユーザー行動データはDBに保存されていないため、協調フィルタリングなどの高度なレコメンデーションは行わない。
- 既存の技術スタック (Next.js, Tailwind CSS, SQLite, etc.) を利用する。
